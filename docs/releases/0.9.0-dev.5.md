# PunPun 0.9.0-dev.5 — Steps 8 and 9 complete

`0.9.0-dev.5` records completion of the planned Step 8 and Step 9 engineering milestones on the Linux x86-64 development host. It advances PunPun from the Step 7 compiler-architecture milestone into structured concurrency, debugging, package integrity, generated documentation, fuzz/compatibility/stress gates and measured performance tooling.

## Step 8: structured async and debugging

- Added runtime task groups with membership, wait/timed-wait, pending/done, cancellation and deterministic close operations.
- Made `sleep_ms` a cooperative cancellation safe point so group cancellation can wake sleeping workers promptly.
- Added typed compiler built-ins for task groups and task-membership checking.
- Extended `std::async` with async file helpers and cancellation-aware delay helpers.
- Added async wrappers across the first-party requests API for task-group composition.
- Added `pp debug-map` for deterministic source/function mappings derived from direct-backend source directives.
- Added `pp debug` to launch GDB/LLDB against a debug build when an installed debugger is available.
- Expanded CI/release qualification with compatibility, fuzz and structured-async gates.
- Reworked Arch package qualification to execute in a current Arch Linux Docker environment instead of assuming GitHub Actions tooling exists inside a minimal Arch job container.

## Step 9: ecosystem, security and production hardening

- PPX publish archives now embed deterministic `PPX-MANIFEST.json` file digests/sizes.
- Added `ppx verify` for offline package-integrity verification and manifest validation on download/install when present.
- Remote non-loopback registries require HTTPS unless an explicit insecure development override is enabled.
- Added `ppx audit [--deny-injection]` for materialized dependency inspection and native-injection policy checks.
- Added deterministic generated API documentation from standard-library and first-party package source, exposed through `pp doc` and `pp doc --check`.
- Added explicit compiler-checked/runnable documentation examples through `pp test --doc`.
- Added deterministic frontend mutation fuzzing with reproduction capture, a direct/C/LLVM compatibility matrix and repeated structured-async stress tests.
- Added portable-C profile-guided optimization through `pp pgo`, including instrumented training and profile-use rebuilds.
- Integrated generated-doc, doctest, fuzz, compatibility and async-stress gates into Makefile/CI/release workflows.

## Deliberate boundaries

The async requests API currently runs the existing synchronous libcurl operation within a PunPun worker task; it is concurrent but not a native nonblocking socket reactor. PPX provides integrity verification and HTTPS policy but not public-key publisher signing. PGO currently targets the portable-C backend rather than the direct x86-64 emitter.

Arch and Windows remain separately qualified release targets. Workflow improvements are not represented as successful platform qualification until a real run passes.
